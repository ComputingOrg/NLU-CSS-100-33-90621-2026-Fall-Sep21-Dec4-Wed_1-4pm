01 · Define before designing

Start with the problem contract

A reliable solution begins by agreeing on what goes in, what must come out, and which rules apply.

Input

What data is supplied? Name its type, units, allowed range, and whether it can be missing or empty.

Output

What exact answer is required? Specify format, units, and what to do when there is no ordinary answer.

Constraints

Limits, business rules, invalid values, ties, duplicates, and assumptions are part of the problem—not details to guess later.

Example contract · adult pass

Input: age, a whole number from 0 through 120. Output: “Eligible” or “Not eligible.” Rule: a pass is available at age 18 or older.

Writing the contract is like checking a recipe before cooking: quantities and desired result must be clear.

01 · Сначала определить задачу

Начните с условий задачи

Надёжное решение начинается с понимания входных данных, требуемого результата и действующих правил.

Входные данные

Какие данные предоставлены? Укажите их тип, единицы, допустимый диапазон и могут ли они отсутствовать или быть пустыми.

Результат

Какой именно ответ требуется? Уточните формат, единицы и действия, если обычного ответа нет.

Ограничения

Пределы, правила, недопустимые значения, равенства, дубликаты и допущения — это часть задачи, а не то, что нужно угадывать.

Условия примера · абонемент для взрослых

Вход: возраст — целое число от 0 до 120. Результат: «Можно оформить» или «Нельзя оформить». Правило: абонемент доступен с 18 лет включительно.

Определить условия задачи — всё равно что проверить рецепт перед приготовлением: должны быть понятны количества и желаемый результат.

01 · Define antes de diseñar

Empieza con el contrato del problema

Una solución fiable comienza por acordar qué datos entran, qué resultado debe salir y qué reglas se aplican.

Entrada

¿Qué datos se proporcionan? Indica tipo, unidades, rango permitido y si pueden faltar o estar vacíos.

Salida

¿Qué respuesta exacta se necesita? Especifica formato, unidades y qué hacer si no existe una respuesta normal.

Restricciones

Límites, reglas, valores inválidos, empates, duplicados y supuestos forman parte del problema; no son detalles para adivinar después.

Contrato de ejemplo · pase para adultos

Entrada: edad, número entero entre 0 y 120. Salida: «Elegible» o «No elegible». Regla: el pase está disponible a partir de los 18 años.

Definir el contrato es como revisar una receta antes de cocinar: las cantidades y el resultado deseado deben estar claros.

02 · Quality and correctness

What makes an algorithm?

An algorithm is a finite, ordered set of unambiguous steps that transforms valid input into the required output.

Clear

Each step has one understandable meaning. A person or computer should not need to guess.

Finite

It finishes after a limited number of steps for the inputs covered by the problem.

Effective

Every instruction can actually be carried out with the available data and operations.

Correct

For every valid input, it produces an output that satisfies the problem rules.

Correctness, in plain words

Ask: “If I follow these steps exactly, do I always get the promised result?” An algorithm that prints an answer quickly but uses the wrong rule is not correct.

Everyday analogy · a bus route

A useful route has clear stops, a destination, and a way to make progress. “Keep riding forever” is not a complete route; neither is “go somewhere nearby.”

Testing examples gives evidence, but a few successful examples alone do not prove correctness for every allowed input.

02 · Качество и корректность

Что такое алгоритм?

Алгоритм — это конечная упорядоченная последовательность однозначных шагов, которая преобразует допустимые входные данные в требуемый результат.

Понятный

У каждого шага есть ясный смысл. Человеку или компьютеру не приходится догадываться.

Конечный

Для рассматриваемых входных данных он завершается за ограниченное число шагов.

Выполнимый

Каждую инструкцию можно выполнить с имеющимися данными и операциями.

Корректный

Для любых допустимых входных данных он выдаёт результат, удовлетворяющий правилам задачи.

Корректность простыми словами

Спросите: «Если точно выполнить эти шаги, всегда ли получится обещанный результат?» Алгоритм, который быстро печатает ответ, но использует неверное правило, некорректен.

Бытовая аналогия · маршрут автобуса

Хороший маршрут имеет понятные остановки, цель и способ продвигаться к ней. «Ехать бесконечно» — не полный маршрут; «поехать куда-нибудь поблизости» — тоже.

Примеры при тестировании дают полезные свидетельства, но несколько успешных примеров сами по себе не доказывают корректность для всех допустимых данных.

02 · Calidad y corrección

¿Qué es un algoritmo?

Un algoritmo es un conjunto finito y ordenado de pasos inequívocos que transforma una entrada válida en la salida requerida.

Claro

Cada paso tiene un significado comprensible. Nadie debería tener que adivinar.

Finito

Termina después de un número limitado de pasos para las entradas contempladas.

Efectivo

Cada instrucción se puede ejecutar con los datos y operaciones disponibles.

Correcto

Para toda entrada válida, produce una salida que cumple las reglas del problema.

Corrección en palabras sencillas

Pregunta: «Si sigo estos pasos exactamente, ¿obtendré siempre el resultado prometido?» Un algoritmo que imprime una respuesta rápidamente pero usa una regla equivocada no es correcto.

Analogía cotidiana · una ruta de autobús

Una ruta útil tiene paradas claras, un destino y una forma de avanzar. «Sigue viajando para siempre» no es una ruta completa; tampoco lo es «ve a algún lugar cercano».

Probar ejemplos aporta evidencia, pero unos pocos casos exitosos no demuestran por sí solos la corrección para todas las entradas permitidas.

03 · A shared notation

Pseudocode is a readable draft

It describes logic without requiring the exact punctuation or syntax of one programming language. Conventions can vary; consistency and clarity matter most.

Useful conventions
  • INPUT reads; OUTPUT shows a result.
  • ← means “store this value in.”
  • IF / ELSE / END IF makes choices visible.
  • FOR / END FOR and WHILE / END WHILE mark repetition.
Make it easy to follow
  • Indent the steps inside a decision or loop.
  • Use names such as total, score, and isEligible.
  • Write one logical action per line.
  • Explain unusual assumptions in a short note.

A complete tiny example

INPUT age
IF age >= 18 THEN
    OUTPUT "Eligible"
ELSE
    OUTPUT "Not eligible"
END IF

Here >= means “greater than or equal to,” so exactly 18 is included.

03 · Общая запись

Псевдокод — это понятный черновик

Он описывает логику без требований к точной пунктуации или синтаксису одного языка программирования. Соглашения могут различаться; важнее всего последовательность и ясность.

Полезные обозначения
  • INPUT считывает данные; OUTPUT показывает результат.
  • ← означает «сохранить это значение в переменной».
  • IF / ELSE / END IF явно показывает выбор.
  • FOR / END FOR и WHILE / END WHILE обозначают повторение.
Пишите понятно
  • Делайте отступы внутри ветвления или цикла.
  • Используйте имена total, score и isEligible.
  • Пишите по одному логическому действию в строке.
  • Необычные допущения поясняйте коротким примечанием.

Короткий законченный пример

INPUT age
IF age >= 18 THEN
    OUTPUT "Можно оформить"
ELSE
    OUTPUT "Нельзя оформить"
END IF

Здесь >= означает «больше или равно», поэтому возраст ровно 18 включён.

03 · Una notación compartida

El pseudocódigo es un borrador legible

Describe la lógica sin exigir la puntuación o sintaxis exacta de un lenguaje concreto. Las convenciones pueden variar; lo más importante es la coherencia y la claridad.

Convenciones útiles
  • INPUT lee datos; OUTPUT muestra un resultado.
  • ← significa «guardar este valor en».
  • IF / ELSE / END IF hace visibles las decisiones.
  • FOR / END FOR y WHILE / END WHILE marcan la repetición.
Facilita la lectura
  • Indenta los pasos dentro de una decisión o un bucle.
  • Usa nombres como total, score e isEligible.
  • Escribe una acción lógica por línea.
  • Explica los supuestos inusuales con una nota breve.

Un ejemplo breve completo

INPUT age
IF age >= 18 THEN
    OUTPUT "Elegible"
ELSE
    OUTPUT "No elegible"
END IF

Aquí >= significa «mayor o igual que», así que se incluye la edad exacta de 18.

04 · Remembering values

Variables and assignment

A variable is a named place to keep a value while an algorithm runs. Think of a labeled jar: the label tells you what the contents mean.

Assignment updates a variable

score ← 6
score ← score + 2

After line 1, score is 6. Line 2 reads the old value (6), adds 2, and stores 8 back into the same variable.

Assignment is not equality

score ← score + 2 is an instruction to change memory. It does not claim that a number equals itself plus two at the same instant.

In many programming languages assignment uses =; pseudocode uses the arrow to make the direction clear.

Good names

itemPrice, count, average, hasTicket

Avoid mystery names

x, thing2, or temp when a meaningful name would explain the value.

Types matter

Age is a whole number; price can have decimals; “has ticket” is true or false; a name is text.

Before tracing, write down each variable’s starting value. If there is no starting value, initialize it before using it.

04 · Хранение значений

Переменные и присваивание

Переменная — это именованное место для хранения значения во время работы алгоритма. Представьте банку с ярлыком: ярлык объясняет, что лежит внутри.

Присваивание обновляет переменную

score ← 6
score ← score + 2

После первой строки score равно 6. Вторая строка читает старое значение (6), прибавляет 2 и сохраняет 8 в той же переменной.

Присваивание — не равенство

score ← score + 2 — команда изменить память. Она не утверждает, что число в тот же момент равно самому себе плюс два.

Во многих языках программирования для присваивания используют =; стрелка в псевдокоде явно показывает направление.

Хорошие имена

itemPrice, count, average, hasTicket

Избегайте загадочных имён

x, thing2 или temp, если осмысленное имя лучше объясняет значение.

Типы важны

Возраст — целое число; цена может быть дробной; наличие билета — истина или ложь; имя — текст.

Перед трассировкой запишите начальные значения всех переменных. Если значения ещё нет, задайте его перед использованием.

04 · Recordar valores

Variables y asignación

Una variable es un lugar con nombre donde se guarda un valor mientras se ejecuta un algoritmo. Imagínala como un frasco etiquetado: la etiqueta explica su contenido.

La asignación actualiza una variable

score ← 6
score ← score + 2

Después de la primera línea, score vale 6. La segunda lee el valor anterior (6), suma 2 y guarda 8 en la misma variable.

Asignar no es comparar

score ← score + 2 es una instrucción para cambiar la memoria. No afirma que un número sea igual a sí mismo más dos al mismo tiempo.

Muchos lenguajes usan = para asignar; la flecha del pseudocódigo deja clara la dirección.

Buenos nombres

itemPrice, count, average, hasTicket

Evita nombres misteriosos

x, thing2 o temp cuando un nombre significativo explique mejor el valor.

Los tipos importan

La edad es un entero; el precio puede tener decimales; tener entrada es verdadero o falso; un nombre es texto.

Antes de hacer una traza, anota el valor inicial de cada variable. Si aún no tiene valor, inicialízala antes de usarla.

05 · Control flow · sequence

Sequence: order changes the result

In a sequence, instructions run from top to bottom. Each step can use values created by earlier steps.

Calculate a café bill

INPUT price
INPUT tipRate
tip ← price * tipRate
total ← price + tip
OUTPUT total

If price is 20 and tipRate is 0.15, the tip is 3 and the total is 23.

Why this order?

  1. Read the original price and tip rate.
  2. Calculate the tip from those known values.
  3. Add the tip to the price.
  4. Show the finished total.

If we calculate total before assigning tip, the algorithm tries to use a value it does not yet have. Order is part of the logic.

05 · Порядок выполнения · последовательность

Последовательность: порядок меняет результат

В последовательности команды выполняются сверху вниз. Каждый шаг может использовать значения, созданные предыдущими шагами.

Рассчитать счёт в кафе

INPUT price
INPUT tipRate
tip ← price * tipRate
total ← price + tip
OUTPUT total

Если цена равна 20, а ставка чаевых — 0,15, чаевые составят 3, а итог — 23.

Почему именно такой порядок?

  1. Считать исходную цену и ставку чаевых.
  2. Рассчитать чаевые по известным значениям.
  3. Прибавить чаевые к цене.
  4. Показать итоговую сумму.

Если рассчитать total до присваивания tip, алгоритм попытается использовать ещё не заданное значение. Порядок — часть логики.

05 · Flujo de control · secuencia

Secuencia: el orden cambia el resultado

En una secuencia, las instrucciones se ejecutan de arriba abajo. Cada paso puede usar valores creados anteriormente.

Calcular la cuenta de una cafetería

INPUT price
INPUT tipRate
tip ← price * tipRate
total ← price + tip
OUTPUT total

Si el precio es 20 y la propina es 0,15, la propina vale 3 y el total es 23.

¿Por qué este orden?

  1. Leer el precio inicial y la tasa de propina.
  2. Calcular la propina con esos datos conocidos.
  3. Sumarla al precio.
  4. Mostrar el total final.

Si calculamos total antes de asignar tip, el algoritmo intenta usar un valor que aún no existe. El orden forma parte de la lógica.

06 · True or false?

Boolean conditions and boundaries

A condition is an expression whose answer is either true or false. Decisions and loops depend on that answer.

OperatorMeaningExample
==is equal toage == 18
!=is not equal tocode != 0
<, >less than, greater thanscore > 70
<=, >=less/greater than or equal toage >= 18

Boundary check

For “age is at least 18,” test 17, 18, and 19. The boundary itself reveals whether the rule should use > or >=.

isEligible ← (age >= 18) AND hasID

Both conditions must be true. An adult without an ID, or a minor with an ID, does not pass this rule.

Words such as “at least,” “no more than,” and “between” hint at inclusive boundaries. Translate the wording before choosing the operator.

06 · Истина или ложь?

Логические условия и границы

Условие — это выражение, результат которого — истина или ложь. От этого результата зависят ветвления и циклы.

Проверка границ

Для правила «возраст не меньше 18» проверьте 17, 18 и 19. Граничное значение показывает, нужен ли оператор > или >=.

07 · Control flow · selection

Selection: choose a path

An IF statement asks a yes/no question and executes the matching branch. The condition controls which steps happen.

Three grade bands

INPUT score
IF score >= 90 THEN
    OUTPUT "A"
ELSE IF score >= 80 THEN
    OUTPUT "B"
ELSE IF score >= 70 THEN
    OUTPUT "C"
ELSE
    OUTPUT "Keep practicing"
END IF

Why check from highest down?

For a score of 92, the first condition is true, so the algorithm stops checking later alternatives. If we checked “score ≥ 70” first, 92 would be labeled C.

Contract: this sample assumes scores are valid numbers from 0 to 100. Decide separately how to handle out-of-range input.

With exactly one path required, use an IF / ELSE IF / ELSE chain. Independent IF statements may each run.

07 · Поток выполнения · выбор

Ветвление: выберите путь

Оператор IF задаёт вопрос с ответом «да» или «нет» и выполняет подходящую ветвь. Условие определяет, какие шаги произойдут.

Три диапазона оценки

INPUT score
IF score >= 90 THEN
    OUTPUT "A"
ELSE IF score >= 80 THEN
    OUTPUT "B"
ELSE IF score >= 70 THEN
    OUTPUT "C"
ELSE
    OUTPUT "Нужно больше практики"
END IF

Почему проверять от большего к меньшему?

Для результата 92 первое условие истинно, поэтому дальнейшие варианты не проверяются. Если сначала проверить «score ≥ 70», результат 92 получит оценку C.

Условия примера: предполагается, что оценка — допустимое число от 0 до 100. Обработку значений вне диапазона нужно определить отдельно.

Если нужен ровно один путь, используйте цепочку IF / ELSE IF / ELSE. Несколько независимых операторов IF могут выполниться все.

07 · Flujo de control · selección

Selección: elige un camino

Una instrucción IF formula una pregunta de sí o no y ejecuta la rama correspondiente. La condición controla qué pasos ocurren.

Tres niveles de calificación

INPUT score
IF score >= 90 THEN
    OUTPUT "A"
ELSE IF score >= 80 THEN
    OUTPUT "B"
ELSE IF score >= 70 THEN
    OUTPUT "C"
ELSE
    OUTPUT "Sigue practicando"
END IF

¿Por qué comprobar de mayor a menor?

Con una puntuación de 92, la primera condición es verdadera y ya no se revisan las alternativas siguientes. Si comprobáramos primero «score ≥ 70», 92 recibiría una C.

Contrato: este ejemplo supone que las puntuaciones son números válidos entre 0 y 100. Define por separado cómo tratar valores fuera de rango.

Cuando se necesita exactamente un camino, usa una cadena IF / ELSE IF / ELSE. Varias instrucciones IF independientes pueden ejecutarse todas.

08 · Control flow · iteration

Iteration: repeat work safely

A loop repeats steps. Before writing one, identify what starts it, when it stops, and how each repetition makes progress.

FOR · known number of repetitions

FOR day ← 1 TO 3
    OUTPUT day
END FOR

The loop handles day 1, then 2, then 3: three times in total.

WHILE · repeat while a condition holds

cupCount ← 0
WHILE cupCount < 3
    cupCount ← cupCount + 1
END WHILE

The update moves the value toward 3. Without the update, the condition would remain true forever.

Start

Initialize the loop variable or state before the first check.

Stop

State the exact stopping condition and check whether the boundary is included.

Progress

Update something that eventually makes the stop condition true.

For a loop over a list, an empty list means zero repetitions. Make sure the result still makes sense in that case.

08 · Поток выполнения · повторение

Цикл: безопасное повторение действий

Цикл повторяет шаги. До его записи определите начальное состояние, условие остановки и способ продвижения на каждом повторе.

FOR · известное число повторов

FOR day ← 1 TO 3
    OUTPUT day
END FOR

Цикл обрабатывает дни 1, затем 2, затем 3 — всего три раза.

WHILE · повторять, пока условие истинно

cupCount ← 0
WHILE cupCount < 3
    cupCount ← cupCount + 1
END WHILE

Обновление приближает значение к 3. Без него условие оставалось бы истинным бесконечно.

Начало

Задайте начальное значение переменной или состояния до первой проверки.

Остановка

Укажите точное условие остановки и проверьте, включена ли граница.

Продвижение

Обновляйте значение так, чтобы условие остановки в итоге стало истинным.

08 · Flujo de control · iteración

Iteración: repetir el trabajo con seguridad

Un bucle repite pasos. Antes de escribirlo, identifica cómo empieza, cuándo termina y cómo avanza cada repetición.

FOR · cantidad de repeticiones conocida

FOR day ← 1 TO 3
    OUTPUT day
END FOR

El bucle procesa el día 1, después el 2 y luego el 3: tres veces en total.

WHILE · repetir mientras se cumpla una condición

cupCount ← 0
WHILE cupCount < 3
    cupCount ← cupCount + 1
END WHILE

La actualización acerca el valor a 3. Sin ella, la condición seguiría siendo verdadera para siempre.

Inicio

Inicializa la variable o el estado antes de la primera comprobación.

Parada

Indica la condición exacta de parada y comprueba si el límite se incluye.

Avance

Actualiza algo que finalmente haga verdadera la condición de parada.

Al recorrer una lista, una lista vacía implica cero repeticiones. Asegúrate de que el resultado también tenga sentido en ese caso.

09 · Two common loop tools

Counters and accumulators

A counter tracks how many events happened. An accumulator combines values into a running result.

Counter · count positive numbers
positiveCount ← 0
FOR each value in values
    IF value > 0 THEN
        positiveCount ← positiveCount + 1
    END IF
END FOR

It starts at zero and increases by one only when an item meets the condition.

Accumulator · add all prices
total ← 0
FOR each price in prices
    total ← total + price
END FOR

It starts with the additive identity, zero, and adds each new value to the running total.

A common pairing · average

total ← 0
count ← 0
FOR each score in scores
    total ← total + score
    count ← count + 1
END FOR
IF count > 0 THEN
    average ← total / count
ELSE
    OUTPUT "No scores were provided"
END IF

Do not divide by zero. Decide what an empty collection means before calculating an average.

Start with a high-level plan. Repeatedly replace each broad action with smaller actions that are specific enough to perform or test.

16 · When the result is wrong

Debug with a method—not a guess

A bug is a mismatch between intended behavior and actual behavior. Find the earliest step where the state becomes wrong.

The total is too large

total ← 0
FOR each price in prices
    total ← total + price
    total ← total + price   // suspicious duplicate
END FOR

For prices [2, 3], the intended total is 5. A trace shows 4 after the first item and 10 after the second: each price is added twice.

A calm debugging routine

  1. Reproduce the problem with a small known input.
  2. Write the expected result and the actual result.
  3. Trace variable values, one step at a time.
  4. Find the first divergence; inspect its condition and update.
  5. Change one cause, then rerun the same tests and nearby edge cases.
Logic bug

The program runs, but follows the wrong rule or order.

Syntax error

The language cannot parse the instructions, such as a missing brace or colon.

Runtime error

The program starts but fails while running, for example by dividing by zero.

Changing many lines at once makes cause and effect hard to see. Make one focused fix and verify it.

16 · Cuando el resultado es incorrecto

19 · Mastery check · pause and answer

Can you explain the logic?

Answer each question before opening its feedback. Try to explain your reasoning, not just name a keyword.

1 · A fee applies at age 18 or older. Which condition?

age >= 18. The words “or older” include 18. Using > 18 would incorrectly exclude the boundary.

2 · A loop count never changes. What can happen?

If its condition stays true, the loop may never end. Initialize state and make a progress update that eventually makes the stop condition true.

3 · Why initialize a total to zero?

Every value can then be added to a known starting point. An uninitialized total may contain no usable value; a stale value can contaminate the answer.

4 · Which case tests a threshold of 50 best?

Use values just below (49.99), exactly at (50), and just above (50.01). Together they expose boundary mistakes.

5 · What does a trace table tell you?

It shows how variable state and decisions change for selected inputs. It helps locate a bug, but it is not by itself proof for every possible input.

6 · Python works; Java gives a different answer. What next?

Compare the language-neutral condition and each variable update line by line. Run the same boundary test in both and locate the first divergence.

Mastery looks like this: you can state the contract, trace an example, justify a boundary operator, and explain why your tests matter.

19 · Comprueba lo aprendido · detente y responde

¿Puedes explicar la lógica?

Responde cada pregunta antes de abrir su explicación. Intenta justificar tu razonamiento, no solo nombrar una palabra clave.

1 · La tarifa se aplica desde los 18 años. ¿Qué condición?

age >= 18. «Desde los 18» incluye esa edad. Usar > 18 excluiría incorrectamente el límite.

2 · El contador de un bucle nunca cambia. ¿Qué puede ocurrir?

Si la condición sigue siendo verdadera, el bucle quizá nunca termine. Inicializa el estado y añade un avance que finalmente haga verdadera la condición de parada.

3 · ¿Por qué inicializar el total en cero?

Así cada valor se suma a un punto de partida conocido. Un total sin inicializar quizá no tenga un valor utilizable; un valor antiguo puede contaminar el resultado.

4 · ¿Qué casos comprueban mejor un umbral de 50?

Usa valores justo por debajo (49,99), exactamente en 50 y justo por encima (50,01). En conjunto revelan errores de límite.

5 · ¿Qué te dice una tabla de seguimiento?

Muestra cómo cambian el estado de las variables y las decisiones para ciertas entradas. Ayuda a localizar errores, pero no demuestra por sí sola todos los casos posibles.

6 · Python funciona y Java da otra respuesta. ¿Qué haces?

Compara línea por línea la condición independiente del lenguaje y las actualizaciones de variables. Ejecuta la misma prueba límite en ambos y localiza la primera diferencia.

Your algorithm design checklist

When you face a new programming task, use this sequence before reaching for syntax.

Design

  • State inputs, outputs, constraints, and assumptions.
  • Choose clear variable names and initialize values.
  • Refine the plan into ordered, unambiguous steps.
  • Identify sequence, decisions, loops, and their boundaries.
