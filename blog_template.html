Writing Commit Messages Your Future Self Will Thank You For

When I first started using Git, most of my commit messages looked like "fixed stuff" or "update html". While working on the Corporate Directory Integration project in CSS:100, I quickly learned why vague commit histories break down on real engineering teams.

A strong commit message answers two questions: what changed and why it was necessary. Using the imperative mood keeps logs consistent and easy to scan: 

git commit -m "Add student profile card to CSS:100 directory"

Treating every commit like a miniature piece of documentation makes code reviews faster and debugging far less stressful.

Breaking Big Problems Into Small HTML & CSS Components

Staring at a blank editor when building a webpage from scratch can feel overwhelming. Applying decomposition—one of the core pillars of computational thinking—turned a daunting portfolio assignment into manageable steps.

Instead of styling everything at once, I sketched the page as four independent blocks: a sticky navigation bar, a two-column hero header, a coursework grid, and a footer. Building and testing one section at a time prevented layout bugs from cascading across the whole page.
